How you can use it

Run a real shell in the native app. When you focus Chrome, the same session appears as an overlay on the page. Switch tabs — it follows. On a phone with Edge Canary + the sideloaded extension, it can follow there too.

1 · Native

cd app && npm start (or open the packaged .app). Your login shell is a real pty — vim, htop, Cursor agent, anything.

2 · Chrome

Build the extension (cd extension && npm run build), Load unpacked → extension/dist. Cmd-tab to any normal site; the terminal flies in.

3 · Phone

Pack dogsh.crx, sideload into Edge Canary, adb reverse the daemon port, set options to ws://localhost:<port>, open a page — overlay follows. 

# quick path
cd app && npm install && npm start
cd ../extension && npm install && npm run build
# chrome://extensions → Load unpacked → extension/dist

# Edge Canary (Android)
cd extension && npm run pack   # → build/dogsh.crx

Architecture

The shell lives in a Session Host (daemon). Everything you see is a thin face. Ownership is a lease on who may type and resize — not where the process lives. 

Faces  native Electron · Chrome / Edge tabs · optional network PWA
   │  WebSocket  (default ws://127.0.0.1:47703)
   ▼
Face gateway     hello / signal / input / caps
   ▼
Lease arbiter    derives sole | mute | monitor from {visible, focused}
   ▼
Session mux      active session, snapshots, grid broadcast
   ▼
Shell backend    node-pty (live) · guest backend (checkpoint path)
   ▼
Persist          scrollback / grid / titles under ~/.dogsh/state

Derived ownership

Faces report raw focus/visibility. The daemon picks the owner and broadcasts owner-state + leaseRole. No client “claims” the terminal.

Handoff = reveal

Faces stay attached while hidden. Switching surfaces only reveals an already-warm renderer — that’s why the motion feels immediate.

Owner drives size

The owning face reports fitted cols/rows; the daemon resizes the pty and every face follows the grid (critical for TUIs like agent).

Remoteness

Loopback vs remote is observed from the socket address. Tokens gate non-loopback hellos. No ADB-specific hacks in the host.

Current state

Public repo with a working macOS native face, Chrome MV3 overlay, and an experimental Edge Canary Android path. CI packages a debug .app, extension dist/, and .crx.

  • Works today — native ↔ Chrome follow, multi-tab overlay, dynamic grid, flood control, scrollback persistence, Cursor Agent / TUI handoff on desktop.
  • Experimental — Edge Canary on Android sideload; phone sheet resize / maximize; USB adb reverse to a loopback daemon.
  • CI — GitHub Actions on macOS 14 builds the debug app + Chrome extension + Canary crx artifacts.
  • Not yet — migrating a live Mac pty across machines (hot-potato moves authority + scrollback; process continuity needs the guest/webshell backend).

Possibility

The north star is a terminal that stays with you the way a phone call stays with you — desk, browser, pocket — without pasting scrollback or SSHing into a second brain.

  • Same machine continuity is the product now: one pty, many faces, lease-based focus.
  • Cross-device presence is partially here via network faces + phone extension; tightening discovery (one port / rendezvous) so faces can’t drift onto stale endpoints.
  • Cross-machine process continuity is the hard sequel: checkpointable guest shells so a handoff doesn’t restart the world.
  • You can use it as a daily driver for agentic CLI work that must survive cmd-tab, tab switches, and a glance at the phone — as long as you stay on the supported surface set above.
